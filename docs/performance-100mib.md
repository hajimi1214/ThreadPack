# 100 MiB 大文件基线

测量日期：2026-11-22。环境为 Windows 11 Home build 26200、Node.js 24.14.1、npm 11.11.0、Chrome 157.0.8103.80 和 Playwright CLI 0.1.25。总内存约 15.3 GiB，开始测量时可用内存约 3.3 GiB；JSONL 浏览器测试前可用内存约 2.6 GiB。浏览器测试使用生产构建和独立 Playwright Chrome 进程树。

## 输入样本

- JSON 样本恰好 104,857,600 字节，包含一条用户消息和一段填充文本。清理器统计的正文为 104,857,557 字节。
- JSONL 样本恰好 104,857,600 字节，包含 102,400 条记录，每行 1,024 字节，正文合计 101,888,000 字节。
- 样本只含合成 ASCII 文本，不含图片或秘密值。CLI 使用 `--format report`，报告约 1.2 KiB。

## CLI

每种格式各运行三次。耗时包含 Node 进程启动、读取、解析、清理和写报告。工作集由进程运行期间约每 5 ms 采样一次，因此是采样峰值。

| 输入 | 完整运行时间 | 采样峰值工作集 |
| --- | ---: | ---: |
| JSON，单条长消息 | 1,242 / 1,195 / 1,180 ms；中位数 1,195 ms | 640.1 / 656.3 / 630.7 MiB；中位数 640.1 MiB |
| JSONL，102,400 条消息 | 1,734 / 1,710 / 1,646 ms；中位数 1,710 ms | 462.5 / 464.4 / 463.5 MiB；中位数 463.5 MiB |

CLI 没有协作式取消接口。以 Windows 强制终止进程作近似测量，JSON 运行 266 ms、工作集达到 341.7 MiB 时终止耗时 28 ms；JSONL 运行 167 ms、工作集达到 257.5 MiB 时终止也耗时 28 ms。终止时均未生成报告。这不等同于测量交互式 `Ctrl+C`。

## 浏览器

完整导入时间从调用文件选择到首批消息可见且消息列表退出忙碌状态。工作集统计包含该 Playwright 会话的 Chrome 进程树，不包含 Playwright CLI 的 Node 进程。

| 输入 | 完整导入时间 | 空载工作集 | 采样峰值 | 采样增量 | 进程峰值之和上界 |
| --- | ---: | ---: | ---: | ---: | ---: |
| JSON，单条长消息 | 2,033 ms | 617.4 MiB | 1,485.4 MiB | 868.1 MiB | 1,757.6 MiB |
| JSONL，102,400 条消息 | 2,547 ms | 611.3 MiB | 1,438.5 MiB | 827.2 MiB | 1,459.2 MiB |

进程峰值之和是各 Chrome 子进程峰值的相加值，峰值未必同时发生，因此作为上界参考。JSON 完整导入期间采样 10 次，JSONL 采样 76 次。

取消测试在两种时机执行。JSON 读取到 2,490,368 字节时点击取消，44.2 ms 后导入指示器消失。JSONL 读取到全部 104,857,600 字节、界面刚显示“正在解析对话”时点击取消，4.2 ms 后界面清空；这验证了 Worker 同步解析阶段也能由主线程终止。

## 决定

保留 100 MiB 上限，不提高上限，也暂不替换解析流程。两种格式都在约 2.6 秒内完成，浏览器取消响应很快。浏览器完整导入的工作集比空载高约 0.8 GiB，说明目前没有依据提高上限。流式 JSONL 解析可以减少输入文本和行切分的瞬时副本，但解析后的原始与清理消息仍需驻留内存，也不会改善单个大型 JSON 对象的峰值。若后续目标明确要求降低浏览器内存，可先对 JSONL 做独立流式原型并复测，再考虑上限变更。
