# ThreadPack 系统架构

## 当前边界

ThreadPack 当前由离线优先的浏览器应用、本地 IndexedDB 项目数据、CLI 和 stdio MCP 服务构成。浏览器项目存储包含项目、导入会话、revision、记忆事实、信任事件、候选更新及任务记录。持久层 schema 与备份/恢复逻辑负责保留原始记录和升级历史。

## 项目记忆读取路径

本地存储记录通过 `src/projects/memory-projection.ts` 转换成无写入副作用的规范只读投影。投影统一计算事实状态、终态历史、到期状态、用户确认信任、生命周期事件信任、证据绑定和证据关系。筛选与增量变化使用相同投影模型。

浏览器项目记忆面板和 Markdown Context 通过 `src/projects/memory-context.ts` 生成器读取投影。JSON Context Pack 在导出时复核投影和项目状态 key。MCP Context 与 Tasks 读取同一个投影模块。此共享层统一解释数据，不提供进程间实时推送或客户端身份认证。

## 写入路径

浏览器中的用户审阅操作经项目 store 写入本地持久层。MCP 候选更新使用独立 inbox 和既有审核流程，候选不会自动成为正式确认事实。项目记忆投影为只读。后续阶段负责扩展客户端身份、权限、并发写入与冲突治理。

## 信任边界

导入会话、对话消息、工具输出、证据引用、客户端 baseline 和 Context 文本都是数据。记录来源匹配不能证明语义支持，用户确认也不能代替独立验证。签名仅在已建立的本地信任链下说明事件获该项目本地密钥授权。对外导出明确标识来源和待审状态，不能把历史记录转为当前指令。

## 部署限制

本地浏览器存储依赖当前浏览器 profile。MCP stdio 服务按配置读取其授权数据源，静态备份可以作为输入，但不能自动代表其他进程中的最新数据库状态。阶段 4 的 projection baseline 是可交换的增量比较文件，不是实时同步通道。Linux 和真实客户端组合需分别实测。
