ThreadPack 1.2.0 improves the workbench and moves large-file work behind a typed background-processing interface.

### Usability

- Imported conversations open directly in a compact workspace. Export controls remain visible, and mobile cleanup settings expand on demand.
- Tool output, privacy text, and message controls have stronger contrast and more readable type.
- Full-text searches cover original and packed content, including the middle of long messages. Pagination returns the preview to the top.

### Processing

- Files are read with Web Streams in a Web Worker, with reading progress and a cancel-and-clear action.
- Complete archives and cleanup results remain in the worker. The page receives at most 30 bounded message previews per query.
- Complete exports are built in the worker and delivered as transferable ArrayBuffers. Exported content is independent of the visible page.
- Cleanup generations and revisions prevent stale settings from being reused. Failed handoff generation clears the old document and disables its download.

### Offline installation

The hosted app is an installable PWA in supporting browsers. Its Service Worker caches only public application resources. Conversation data and exports are not cached. Updates require explicit acceptance so in-memory work can be downloaded before reloading. The standalone HTML continues to work directly from `file://`.

### Downloads

- **ThreadPack-1.2.0.html** — standalone offline browser application.
- **threadpack-1.2.0.mjs** — CLI for Node.js 20.19 or later.
- **ThreadPack-1.2.0-source.zip** — source, tests, documentation, and synthetic examples.
- **SHA256SUMS.txt** — artifact checksums.

See the architecture document for measured response-size and layout comparisons. Redaction remains heuristic, handoffs remain deterministic excerpts, and normalized exports do not resume native agent sessions.
