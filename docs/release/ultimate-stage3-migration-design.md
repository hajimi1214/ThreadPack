# ThreadPack 阶段 3 设计：完整备份、恢复与历史迁移

日期：2026-11-28

## 真实基线

- 候选分支：`release-candidate/third-round-stage5-baseline`
- 阶段 2 验收提交：`35786ea6e5f16b4b81d26af872890aa1c3e9fbf0`
- IndexedDB schema：v7。阶段 3 不升级数据库版本，避免旧版应用因 `VersionError` 不能打开用户数据库。
- 项目 JSONL 备份：v8
- 恢复入口：`restoreProjectBackup`，先写入隐藏的 `restoringSince` 项目，校验计数、会话修订、证据、生命周期、任务与签名链后才发布项目。
- v1–v8 由同一恢复入口按格式能力逐项兼容。阶段 3 新增逐版本合成夹具和中断/损坏路径回归。

## 阶段 3 目标

将规范备份推进至 v9，并为旧版本导入留下可追溯的迁移记录。v1–v8 源文件继续只读，导入生成新的项目副本。任何旧版确认或签名都不得因导入而自动成为本机已信任状态。

## v9 格式

- 头记录声明 `version: 9`、`migrationCount` 和现有各类数据计数。
- 保留 session、revision、memory、update、claim、trust_state 和 trust_event 原记录语义。
- 追加 `migration` 记录，记录旧格式来源版本、目标格式、迁移规则版本、来源项目标识、来源记录链摘要、逐类记录数和导入时间。迁移记录标记为迁移操作，不代表用户确认或独立验证。
- 以末尾 `manifest` 记录封口。manifest 对有序记录链和逐类计数作 SHA-256 完整性校验。摘要用于检测损坏与遗漏，不是签名，也不证明来源身份或内容真实性。
- 为避免对大型 revision 内容再次整体序列化，链摘要使用已校验的内容指纹与固定字段元数据摘要组成每条记录摘要。

## 持久化与恢复

- 迁移账本以可选 `migrationHistory` 字段保存在现有项目记录内，不改动既有对象 store 或 IndexedDB schema 版本。旧版应用忽略该附加字段仍可读取 v7 项目记录。
- 暂存阶段先在内存完整校验来源记录和已有 migration 记录。所有项目数据写入暂存 ID，最终发布时把账本与清除 `restoringSince` 的项目行更新放在同一事务。中断时项目保持隐藏，清理程序删除暂存项目，原备份可重试。
- 每个项目的迁移记录按确定性迁移 ID 去重，保留源版本、摘要、计数及信任处置结果。
- 旧格式校验完成后写入 `sourceFormatVersion → targetFormatVersion` 迁移记录。版本 1–8 的签名链即使通过数学一致性校验，导入后仍是 `untrusted-import`，事实确认与生命周期信任均按未认证状态恢复。
- 恢复使用隐藏暂存项目。验证失败时删除该暂存项目的全部关联行。若进程中断，项目不会出现在项目列表中，重选原备份可重新导入；过期暂存项目由清理逻辑回收。
- 迁移不覆盖源文件或现有项目。备份文件是迁移前原始副本，失败时继续可用。

## 验收矩阵

- v1–v8 每个格式版本均使用合成文件验证导入、计数、历史内容和迁移记录。
- v9 验证导出与恢复往返、manifest、全部计数、证据指纹、确认与终态历史、密钥状态及不可信引用。
- 篡改、截断、错序、缺失记录和 manifest 不匹配必须失败关闭，且不发布部分项目。
- 对损坏导入执行重试，确认项目行、会话、记忆、事件和迁移账本保持一致。
- MCP 静态备份读取器同时识别 v9 manifest，并拒绝完整性不匹配。
- 类型检查、全量单测、MCP 测试、Chromium/Firefox/WebKit 项目测试、生产构建和备份恢复回归全部记录实际结果。

## 边界

恢复支持的是失败后从保留的原始文件安全重试，不声称可从任意字节偏移继续流式导入。浏览器存储配额、Linux 和设备间恢复需按实际运行结果报告。
